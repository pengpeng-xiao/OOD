Which test samples are out of distribution?

The benchmark ships five DeepONet checkpoints with their training data and a test set per PDE that mixes samples from several regimes, with no labels. I fitted a statistical model of how each problem's training inputs were generated, then tested every test input against it. Scored afterwards against the private split key, the labels are exactly right.

Result

Each scalar PDE's test set splits into one group that matches the training inputs and one or more groups drawn from rougher random fields. Cavity flow splits by the lid amplitude U. Task and ground rules

  • Local access was limited to the benchmark bundle. It contains training data, checkpoints and test sets for diffusion_reaction, burgers, advection, poisson and cavity_flow.
  • I did not look up the data or its source. The detection used only the bundle and general statistics.
  • To run the TensorFlow-v1 checkpoints I built a separate environment (TensorFlow 2.12, DeepXDE 1.9.1). I did not use the existing environment outside the bundle.
  • The labels and the decision threshold were fixed before the private key was opened. The key was read only afterwards, by the scoring script, once you gave access to it.

What the inputs are

Every problem feeds the network a function sampled at 101 points (the branch input) and asks for the solution at a set of coordinates (the trunk input). The detection works on the branch inputs.

Method

  1. First look: run the released models

    I ran every checkpoint on its training set and its test set and compared relative L2 errors per sample. Many test samples had errors far above anything seen in training: 78% for advection, 50% for Poisson, 30% for diffusion–reaction, 10 of 30 for cavity flow, but only 5% for Burgers. Error is a useful signal, but it mixes "unfamiliar input" with "hard input", so I used it only as a cross-check.

  2. Identify how the training inputs were generated

    The empirical covariance of the training inputs depended only on the distance between points, which suggested a stationary Gaussian random field (GRF). I fitted kernel family, length scale l, amplitude σ and noise level (nugget) by maximum likelihood over all 1000 training samples at once.

  3. Score each test sample with a likelihood ratio

    For a test input x, I found the length scale that best explains that single sample, with σ fitted alongside it, and compared the fit with the training length scale:

    score = 2 · [ maxl log p(x | l) − log p(x | ltrain) ]

    The kernel's variance in mode k falls roughly like exp(−c·k²·l²), so a rougher field puts orders of magnitude more energy into modes 6 to 12 than the training model allows. Because the samples are almost noise-free, one 101-point sample pins down its own length scale very precisely.

    For training-distributed samples the score should follow a χ² distribution with one degree of freedom. The 1000 training samples confirmed this, with a maximum near 13. I labelled a sample OOD when p < 10⁻⁴, which means a score above 15.1.

  4. Adjust for each problem's quirks

    • Advection. Inputs are shifted so their minimum is 1 (a = f − min f + 1), which hides the field's own offset. I fitted only the variation around each sample's mean (restricted likelihood).
    • Burgers. Periodic kernel; the last point repeats the first, so I dropped it.
    • Poisson. The training spectrum matches the kernel through mode 10, then drops to the float32 rounding floor. The generator kept only 11 modes, so I restricted the likelihood to them.
    • Cavity flow. The input has a single parameter, so I read off U and compared it with the training range [0, 0.40]. Values inside the range are interpolation (ID); values above it are extrapolation (OOD).

  5. Cross-check with independent signals

    • Model-free distance. Mahalanobis distance in the leading principal directions of the training inputs, with a threshold from 10-fold cross-validation on training data. It makes no kernel assumption and gave AUROC 1.000 on every scalar problem. Burgers needs 14 or more directions (0.972 with 10) because periodic fields carry their information in sin/cos pairs.
    • Poisson tail energy. Energy beyond mode 11 is at most 7.2e-13 in training and 3.1e-13 in ID test samples, but at least 9.3e-6 in OOD test samples. It agrees with the labels on all 200 samples.
    • Model error. On samples labelled ID the error distribution matches training. OOD errors are 5–20× higher, and largest for the roughest regimes.
    • Two-sample tests. KS tests of the ID-labelled test group against training found no difference in fitted length scale, amplitude or model error (p > 0.05), apart from slightly higher error on unseen advection samples (p = 0.026), as expected for a generalisation gap.

  6. Score against the private key

    The key gives a split label (iid or ood) and the source file for every sample ID. evaluate_auroc.py matches sample IDs and reports AUROC for each score, accuracy and the confusion matrix of the hard labels.

What went wrong along the way

  • The first noise level was far too large. With a nugget of 1e-6, the fitted length scale for training samples came out near 0.35 and σ near 0.16, both badly biased. The data are nearly noise-free, so a large nugget hides the high-frequency modes where most of the information lives. Fitting the nugget by pooled likelihood (about 1e-13) fixed it.
  • Poisson did not match the kernel at first. Even with a small nugget its training fits were broad (0.2 to 0.53). Comparing the empirical spectrum with the kernel spectrum showed the truncation after mode 10, and restricting the likelihood to the first 11 modes made the training fits tight around 0.5.
  • Model error alone would not have been enough. On Burgers it reaches AUROC $BU_AUC_ERR, because the network handles the moderately rougher inputs fairly well. Testing the input distribution directly is what made the separation complete.

Caveats

  • The cavity-flow definition is a choice. The 20 ID samples have U values between the training values, not equal to them. I counted them as in-distribution because they are interpolation within the training range, and the key agrees. Under a stricter definition, where only the 21 exact training values count, all 30 would be OOD.
  • The method relies on the inputs' simple structure. It works this well because each problem's training inputs follow a simple parametric model and the regimes differ in one parameter. Without that structure, the model-free distance check (or a learned density model) is the better default.
  • One borderline call by the cross-check. The Mahalanobis check flags one Burgers ID sample just above its 99.9% cross-validation threshold. It is far below every OOD sample, and the main test labels it ID, correctly.
